## Required acceptance sequence

1. Pass the focused static and forced-GPU checks that do not depend on final
   v0.22 browser records, then commit the complete record-stage implementation
   as commit I.
2. From clean commit I, generate its local GPU artifact and run the first
   attended Point-footprint record stage. Retain only the canonical/focused
   baseline PNGs; discard the first-pass manifest and record evidence.
3. Commit only those PNGs, without changing any qualified implementation path.
   That clean commit P is the accepted implementation pin.
4. From clean commit P, regenerate the local GPU artifact, rebuild, and repeat
   record mode. Require byte-identical PNGs and retain only the second pass's
   uncommitted baseline manifest, which pins P without self-reference.
5. At P, repeat the packed quickstart and exact browser qualification to create
   fresh v0.22 functional records. Put P and the qualification-verifier SHA-256
   into this record, and put P into the v0.22 CHANGELOG entry, before running
   the functional static verifiers. Then run the separate attended
   Point-footprint verify stage and place its evidence JSON and bound artifacts
   at their recorded repository-relative paths.
6. Pass:

   ```bash
   node scripts/verify-browser-point-footprint.mjs \
     --baseline docs/releases/v0.22-browser-point-footprint-baseline.json \
     --evidence docs/releases/v0.22-browser-point-footprint-evidence.json
   ```

7. Replace every remaining **PENDING** field below only with the exact final
   observation, then run the complete formatting, lint, test, rustdoc, package,
   JavaScript, benchmark, example, forced-GPU, documentation, JSON, and diff
   matrix in [CONTRIBUTING.md](../../CONTRIBUTING.md).

The detailed attended procedure is in the [browser Point-footprint
guide](../guides/browser-point-footprint.md).
