## Qualified package seam

`@punctra/viewer` exports the framework-neutral `createViewer` entry point,
package-relative asset resolution, public viewer/error/display types, the input
normalizer subpath, and the exact-query subpath. Its export map is closed. The
default Wasm and Worker source URLs remain statically visible through
`new URL(..., import.meta.url)`. Qualified Vite production builds return the
same content-hashed bundled Worker URL that `createViewer()` constructs, while
explicit URLs support copied assets and CDNs. One imported SDK module
initializes exactly one Wasm URL and rejects an attempt to switch URLs after
initialization.

The SDK's optional `cacheKey` is bounded to 1–128 characters and changes only
the `punctra-v` asset query. Failed Wasm initialization can be retried. Worker
creation has one package-private factory seam so Vite can discover the default
module Worker while explicit Worker URLs retain host-owned deployment control.
The inherited viewer now exposes idempotent `dispose()` plus `pause()` and
`resume()` lifecycle aliases without changing the v0.17 state or authority
contracts.

`@punctra/react` exports one `usePunctraViewer` hook. The caller owns the canvas
and viewport. The adapter recreates only when canvas or explicit `mountKey`
identity changes, resizes without recreation, maps `active` to pause/resume,
unsubscribes before disposal, and disposes viewers that resolve after an
abandoned asynchronous mount. Sixty-four abandoned-mount trials and React
Strict Mode runtime mounting exercised that ownership boundary. The packed
runtime trial also verified update-without-recreation, explicit-key recreation,
and final cleanup through the exported hook.

The packed viewer tarball contained exactly 22 declared files, including the
737.2 kB Wasm binary and module Worker; it was 298.2 kB compressed and 958.9 kB
unpacked. The React tarball contained exactly 5 declared files; it was 1.9 kB
compressed and 5.1 kB unpacked. These are generated package observations, not
registry or production transfer-size promises.

## Outstanding exits

- publish and independently install the SDK through a registry rather than
  local packed artifacts;
- qualify production CDN/hosting layouts, content types, CSP, credentials,
  authentication, cache eviction, telemetry, and recovery ownership;
- support arbitrary remote LAS/LAZ, LAZ random access, hierarchy traversal,
  multiple Sources, or another declared deployment profile;
- implement a general authoritative Query bridge, Workspace/revision binding,
  rectangle or polygon selection, or browser editing;
- qualify declared browsers, operating systems, WebGPU adapters, devices,
  representative Sources, storage behavior, framework versions, and failure
  environments;
- measure browser heap, process memory, physical cache allocation, and GPU
  behavior without conflating them with algorithm accounting; and
- obtain independent embedding/adopter evidence before declaring API stability,
  support status, or a browser-engine release candidate.

Until those exits are observed, v0.18 is complete only as the bounded packed
repository slice described above. v0.19 remains a Candidate browser/device
qualification theme; no broad compatibility, product readiness, or release-
candidate status is implied by this record.
