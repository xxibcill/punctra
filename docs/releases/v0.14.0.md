## Qualified exact-QA seam

`point-terrain` now evaluates a caller-declared nonempty combination of an exact
Source `PointQuery`, detached Check Points, and evenly stationed profiles
against one immutable Snapshot/Surface pair. Results retain signed residuals,
Surface elevations, explicit gaps, asymmetric inclusive metre tolerances,
canonical face identities, deterministic input/result hashes, structured
spatial provenance, resource facts, and five-state Snapshot/Surface freshness.

The same operation is available for in-memory and prepared disk-v1 Surfaces.
Prepared QA materializes verified records only under independent read,
materialization, face-test, observation, result, and combined working limits.
Failure and cancellation publish no partial report. An exact query remains
present evidence when it returns zero rows, and its normalized semantics are
part of the input hash.

`compare_surfaces` matches faces by authoritative Point Identity triples rather
than per-Surface vertex numbering. It reports deterministic added and removed
face counts and hashes plus a conservative incident-vertex envelope. It does
not claim that every point inside the envelope changed or that the envelope is
an exact change polygon.

Correction and Revert still use `point-workspace`; v0.14 adds no second edit
model. The public example composes exact QA, a classification correction,
staleness detection, re-derivation, comparison, recheck, and immediate-head
Revert.

### Focused acceptance coverage

The exact-QA integration suite covers analytic profile, Source residual,
detached Check Point, asymmetric tolerance-boundary, and gap outcomes;
prepared/in-memory equality; deterministic results across Source row batching;
golden input/result digests; query-semantic hashing and valid empty queries;
all five freshness states; before/after and post-Revert comparisons; explicit
Source, Recipe, and spatial-reference mismatch rejection; exact-limit success
and one-under failures; and bounded cancellation without partial publication.

The generated correction case changed four added and six removed faces. Its
conservative bounds were `[500000, 4600000, 100]` through
`[500002, 4600002, 110]`. Revert reproduced the baseline topology with zero
added faces, zero removed faces, and no changed bounds.

## Generated example observations

The public `exact_terrain_qa` example generated a 3-by-3 metric grid whose
centre Ground Point was ten metres high. Baseline QA reported one detached
Check Point below the 0.05-metre tolerance and nine other covered residuals
within tolerance. Reclassifying the centre Point removed it from the Ground
Surface: corrected QA reported that Source Point ten metres above the Surface,
the Check Point within tolerance, and nine other covered residuals within
tolerance. This is expected: the exact Source query still observes the
reclassified non-Ground Point even though Terrain derivation no longer uses it.

After correction, the baseline report was
`stale_snapshot_and_surface`. The generated evidence retained exact Workspace,
Source, Revision, operation, Recipe, input, geometry, topology, Artifact,
spatial-reference, query, tolerance, result, and resource facts. The generated
SVG's baseline and corrected station elements map to JSON station pointers.

The example's generated data and elapsed-free resource counters are repository
evidence only. They do not establish a firm's tolerance policy, a useful
professional section layout, field accuracy, time saving, or independent use.
