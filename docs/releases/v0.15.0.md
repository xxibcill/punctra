## Qualified browser seam

The private `browser-demo` package compiles the existing `render-protocol`,
`point-view`, and `render-wgpu` composition to WebAssembly. It creates one
WebGPU surface from a caller-owned `HTMLCanvasElement`, requests core features
and default limits, publishes one deterministic generated batch, records and
presents frames, performs one asynchronous provisional pick, and exposes
bounded JSON diagnostics and explicit safe actions.

The JavaScript caller owns canvas placement, CSS size, device-pixel-ratio,
visibility, scheduling, controls, failure presentation, and recreation policy.
The private Rust adapter owns the WebGPU instance, surface, adapter, device,
queue, configuration, encoders, submissions, presentation, and pick readback
on the caller's behalf. `render-wgpu` still does not own application policy or
submit a caller's queue.

`render-wgpu` now selects `web_time::Instant` on `wasm32`; its native timing
continues to use `std::time::Instant`. This removes the bare-WebAssembly
`Instant::now` trap without changing the renderer protocol or native timing
contract.

The browser boundary is example-only and may be replaced. It does not accept a
Source URL, credentials, arbitrary point arrays, callbacks, shaders,
frameworks, persistent storage, or Edit intent. The generated display and pick
remain progressive GPU evidence, not exact CPU Source authority.
