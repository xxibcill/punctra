# v0.9 Support, Upgrade, and Recovery Matrix

Status: candidate matrix; verified support is limited to the release record

This matrix defines the repository support promise for v0.9. It covers one
local, GPU-free LAS/LAZ classification-correction-to-TIN workflow and the
separately embeddable display interfaces. It does not turn the repository into
a supported desktop product or claim that a downstream vendor executed or
accepted a file.

## Supported workflow profile

| Dimension | Supported in v0.9 | Explicitly unsupported |
|---|---|---|
| Source location | One immutable local regular LAS or LAZ file | Remote objects, URLs, COPC, E57, rewritten Sources, or multiple Sources |
| Point records | LAS formats 0–10; LAZ formats 0–8 | LAZ formats 9–10 until exact WavePacket14 decoding exists |
| Coordinates | Exact stored integer ticks and declared scale/offset; finite `f64` world values | Coordinate repair, axis guessing, rounding as authority, or non-finite values |
| Coordinate reference | WKT metadata is preserved when unambiguous; the Workflow requires an explicit caller assertion that coordinates are metric metres | CRS inference, transformation, datum or geoid conversion, and an inferred vertical reference |
| Units | Metres only for Terrain, QA coordinates, LandXML, and Round-Trip comparison | Feet, US survey feet, unit conversion, or a file that merely appears metrically scaled |
| Workspace | One Source, one selected Source `U8` classification Attribute, exact selection, sparse uniform classification Edit, immediate-head Revert | General Attribute/position editing, branches, merge, compaction, named durable Point Sets, or multiple writers |
| Terrain | One deterministic in-memory unconstrained 2.5D TIN from exact effective class-2 Ground Input, with optional bounds | Persistent Surfaces, Breaklines, boundaries, holes, constrained triangulation, multiple Surfaces, or automatic repair |
| QA | Detached Check Points and exact generated Revision Audit/Edit Footprint facts | General survey adjustment, profiles, sections, or product acceptance decisions |
| LandXML output | Deterministic LandXML 1.2, one metric-metre TIN, canonical points/faces, create-or-exact-reconcile | General LandXML, Breaklines, boundaries, multiple Surfaces, coordinate-system conversion, or overwrite |
| Returned LandXML | One narrow LandXML 1.2 metric-metre TIN; presentation reorder, identifier changes, face order/winding, and bounded metadata differences may be ignored | DTD/entities/XInclude, foreign semantic children, unit/reference drift, ambiguity, topology repair, nearest-match guessing, or partial success |
| Qualification | One strictly revalidated Complete eight-frame Run, one returned file, one complete caller declaration/tolerance policy, and one separate no-replace evidence target | Repairing an incomplete Run, writing evidence inside the Run root, external automation, vendor certification, or proof that declared software ran |
| Rendering | Existing renderer-neutral planning/protocol plus host-owned wgpu recording and provisional picks | GPU-authoritative geometry, host/device/queue ownership, automatic eviction, exact selection from a GPU pick, or a product UI |

Point and face counts, bytes, working memory, comparisons, journal/report size,
and GPU residency are subject to the explicit limit values on their owning
interfaces. Defaults are support ceilings, not performance promises. Raising a
limit does not expand the supported semantic profile.

## Persisted and published formats

| Owner | Format/version | Class | v0.9 policy |
|---|---|---|---|
| `point-source` | `SourceRecord` schema 1, Source contract 1 | Authoritative | Read through an official adapter with Full verification or eligible Fast verification. Unknown versions and changed Source bytes fail closed without rewriting the record. |
| `point-index` | `.pidx` disk 1, recipe 1; valid `.work` prefix | Rebuildable | Open or resume exact supported bytes. A successful build retains the bounded valid `.work`; when both exist, `.pidx` wins and `.work` is untouched. Preserve corrupt/incompatible state for diagnosis; the caller may explicitly remove the complete index family and rebuild from the verified Source. No migration. |
| `point-workspace` | manifest, ready/rejection Operation records, and Revision files at disk 1 / semantic 1 | Authoritative | Reopen and recover through `point-workspace`. Never manually edit, delete, reorder, or rebuild these files. Unknown/corrupt/indeterminate state fails closed. |
| `terrain-demo` | `run.pwf` disk 1 / semantic 1 / frame 1 | Authoritative | Resume or inspect through the owning application. Only inspect may truncate a proven torn final suffix. Qualification is strictly read-only. |
| `terrain-demo` | `audit.json` schema `punctra.terrain-workflow.audit.v1` | Caller-owned published output | Create or reconcile only when exact canonical bytes match. A different target is a conflict, not an upgrade opportunity. |
| `point-terrain` | metric-metre LandXML 1.2 single-TIN `terrain.xml` | Caller-owned published output | Create or reconcile exact bytes; never overwrite. Returned-file comparison does not make general LandXML readable. |
| `terrain-demo` | `punctra.terrain-demo.landxml-round-trip-evidence.v1` | Caller-owned published output | Create or reconcile exact canonical pass/semantic-fail bytes outside the Run root; never overwrite a different record. |
| Owning modules | index sample/stage files, Point Set spills, Workspace candidates, publication stages, and locks | Temporary | No cross-release readability. Production code never unlinks a replaceable temporary pathname. Linux point-index publication stages are unnamed and leave no alias after descriptor close; other private files remain per-attempt bounded debris and retained bytes can accumulate across attempts. Recovery ignores documented private names. Offline cleanup is caller-owned and permitted only while no related Workspace, Run, Point Set, job, or process is live. Unknown siblings and replacements are preserved. |

Cargo `0.9.0`, disk/semantic/recipe/algorithm version 1, and JSON/XML schema
names are independent. Upgrading the package does not rewrite authoritative
bytes. A later package must keep a claimed version readable or publish a
separate tested migration/rebuild rule; v0.9 has no version 2 and therefore no
migration framework.

## Platform and device evidence

The verified repository tier is the exact environment named in the v0.9
release record: Apple arm64 hardware, macOS, the repository-pinned Rust 1.90.0
toolchain, its local filesystem, and the recorded wgpu adapter/backend.

The implementation contains Unix and Windows stable-file-identity paths, but
cross-platform code is not cross-platform release evidence. Platforms or
filesystems without a stable identity required by a publication/revalidation
operation fail closed. Windows, Linux, network filesystems, case-insensitive
alias combinations beyond the verified environment, and other GPUs remain
unverified tiers until their complete local matrix is recorded.

Descriptor-bound no-replace publication is verified only on the recorded local
macOS filesystem. Point-index, Workspace scratch-to-authoritative, LandXML,
report, and evidence publication use `fclonefileat` from already written and
synced open descriptors, producing independent copy-on-write files. The ready
Operation to Revision path is the one intentional authoritative hard-link
identity. Linux point-index publication creates an unnamed `O_TMPFILE` and
assigns exactly one canonical name; LandXML, report, and evidence use the same
unnamed-file principle. These paths fail closed if their filesystem, procfs
path, privileges, or kernel reject the required operation. Named Workspace
scratch publication fails closed on Linux because retaining a linked name
would expose a mutable alias. Other publication targets fail closed.
Point-index and LandXML publication additionally sync an open destination
witness and revalidate that witness against the target leaf after
parent-directory sync. Point-index revalidates the exact initial header or
complete-artifact checksum and retains the same leaf witness throughout a
complete open; exact caller-output reconciliation retains its leaf witness
through acknowledgement and terminal progress.
Publication resolves the caller-provided parent directory at that boundary.
Concurrent replacement of a caller-owned parent-directory namespace is outside
the supported workflow; leaf-name races remain no-replace and preserve the
racing file.

GPU availability is irrelevant to the authoritative Source/Workspace/Terrain
workflow. It is required only for the two local renderer acceptance commands.
A missing adapter is a failure when those commands run with
`PUNCTRA_REQUIRE_GPU=1`; it does not justify using display state as authority.

## Recovery playbook

Preserve all authoritative files until the owning interface reports a
reconciled state. Do not infer durability from a pathname alone.

| Observed condition | Safe action |
|---|---|
| Invalid request or unsupported semantic input before publication | Correct the named request/profile and start or retry as instructed. Do not mutate persisted bytes to make them parse. |
| Resource limit before an ambiguous publication point | Narrow the exact request or deliberately raise the named limit, then retry through the same owning interface. |
| Source missing or changed | Restore the exact immutable Source bytes. A replacement Source is a different authority and requires a new index/Workspace/Run. |
| Complete or work index is incompatible/corrupt | Preserve it for diagnosis. After confirming the immutable Source, explicitly remove the index-owned family and rebuild; never delete Workspace/Run state as part of index cleanup. |
| Valid resumable index work | Call `point_index::prepare` again with the same Source, target, recipe, and limits. It resumes only verified frames. |
| Workspace commit is retryable or indeterminate | Drop the poisoned handle, reopen the Workspace, resolve the recorded Operation, and use `retry_operation` or the Workflow's same-identity resume path. Never invent a new Operation for the same uncertain intent. |
| Run is incomplete but valid | Invoke `terrain-demo resume` with exactly the original identities, paths, and intent. |
| Run has a proven torn final journal suffix | Invoke `terrain-demo inspect` or resume; the owning journal may repair only that suffix. Qualification never repairs it. |
| Authoritative corruption, unknown version, lineage mismatch, or unresolved indeterminate state | Stop and preserve Source, Workspace, Run, and published outputs. Restore from a known exact backup or escalate with the bounded diagnostic; do not hand-edit. |
| Existing LandXML/report/evidence differs from canonical bytes | Remove or rename the caller-owned conflicting target only after deciding which deliverable to retain, then retry. The application never overwrites it. |
| Publication certainty is indeterminate | Reopen/retry through the same owning interface so it can read back and reconcile the exact expected hash. Do not report success from the first error. |
| Semantic Round-Trip result is `failed` | Retain the failed evidence, review downstream settings or reject the returned deliverable. Retrying identical inputs deterministically reconciles the same record. |
| Recognized private stages or spills remain | Stop all related Workspace, Run, Point Set, and publication jobs, preserve unknown siblings, then remove only the documented private-name family as offline caller-owned maintenance. Do not treat retained temporary bytes as a published fact. |
| GPU adapter/device unavailable or lost | Preserve CPU-authoritative state, recreate host-owned GPU state, and rerun display acceptance. No Workspace or Terrain recovery is required. |

Backups of authoritative state must include the immutable Source, the complete
Workspace root, and the Run root as coherent sets. An index can be rebuilt, but
restoring only selected Workspace Revision or Operation files is unsupported.
Caller-owned LandXML, report, and evidence files may be archived independently
when their hashes and Run bindings are retained.

## Nonclaims

This matrix records repository behavior only. It does not claim a production
workstation tier, licensed or sanitized customer corpus, above-500-million-
Point Terrain completion, observed Autodesk/Bentley execution, vendor
certification, firm acceptance, paid use, conversion, measured labor savings,
installer/update support, an operational support team, or a maintained product
service-level agreement. Those facts require separate authorized evidence.
